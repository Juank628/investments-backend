# Generate CRUD endpoint

Scaffolds a REST endpoint for one Sequelize model in this repo, matching
this repo's established controller-route-app.ts pattern exactly.

Two bundled resources, read both before writing code:

- `references/conventions.md` — the **rules**: field selection, status
  codes, naming, pluralization, the traps. It has all the detail this file
  intentionally leaves out.
- `references/examples/` — the **exact shape**: one complete, compiling
  endpoint (model → types → controller → route → `app.ts`) generated by
  this skill for `src/models/VerticalSpread.ts`. Imitate it; don't copy it
  into `src/`.

## Required inputs

1. **Model path** — e.g. `src/models/Product.ts`.
2. **Methods to implement, each with its allowed roles** — e.g.
   `GET: [admin, viewer, editor], POST: [admin], PUT: [admin], DELETE: [admin]`.

If either is missing or a method's role list is empty/unclear, ask before
writing code — getting a role list wrong is a security mistake, not a style
one, so don't guess it. The only valid roles are `admin`, `editor`, and
`viewer`.

Only implement the methods actually given. Don't add a method "for
completeness" — an omitted method means the developer doesn't want it yet.

## Workflow

1. **Read the model file.** Note: the exported model variable name, the
   `I<Model>` interface, every field's type/`allowNull`/`defaultValue`, and
   which field is `primaryKey: true`. This drives naming and body
   validation — see `references/conventions.md` for the exact rules, and
   `references/examples/VerticalSpread.model.ts` for the model those rules
   were worked through.

2. **Derive the resource base name.** Pluralized camelCase of the model
   name (e.g. `Product` → `products`) — see `references/conventions.md`
   for the exact pluralization/kebab-casing rule and a multi-word example.
   This is the shared base for the controller filename, route filename,
   and (kebab-cased) URL path. If pluralization is awkward or ambiguous,
   ask rather than guess.

3. **Ensure `src/controllers/helpers.ts` exists.** Every generated
   controller imports its shared checks from here instead of redeclaring
   them. Target content is `references/examples/helpers.ts`:

   ```ts
   export const UUID_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

   //0 and false are valid values, so only null/undefined/'' count as missing
   export const isMissing = (value: unknown): boolean =>
     value === undefined || value === null || value === '';
   ```

   - File doesn't exist → create it with exactly that.
   - File exists but is missing one of the exports → append only the
     missing one.
   - File exists with both → leave it untouched.
   - A model with an integer PK needs a digits guard as well; add it to
     this file under the same rule rather than inlining it.

4. **Write `src/controllers/<base>.types.ts`** (only if POST and/or PUT is
   requested) with request-body interfaces. See
   `references/examples/verticalSpreads.types.ts`, and the reference for
   exactly which fields are required vs. optional vs. excluded.

5. **Write `src/controllers/<base>.ts`** with only the requested handlers
   (`getAll<Model>s`, `get<Model>ById`, `create<Model>`, `update<Model>`,
   `delete<Model>`), mirroring
   `references/examples/verticalSpreads.controller.ts`: async
   `(req, res, next)`, 422 on missing required body fields (with the same
   `{ error, details }` shape), 404 when a row isn't found, try/catch
   around DB calls calling `next(error)` on failure. Full status-code table
   is in the reference. Start the file with
   `import { UUID_REGEX, isMissing } from './helpers';` and use them for
   the two traps that must not be skipped:

   - `isMissing` for every required-field check — a plain `!field` wrongly
     rejects `0` and `false`.
   - `UUID_REGEX.test(id)` at the top of every `:id` handler, returning the
     normal 404 — an unguarded malformed UUID reaches Postgres, errors, and
     `next(error)` turns it into a 500 stack trace because there's no error
     middleware.

6. **Write `src/routes/<base>.ts`**, mirroring
   `references/examples/verticalSpreads.route.ts`: one `router.<verb>(...)`
   per requested method, each wrapped in `verifyRoles([...roles])` using
   exactly the roles supplied for that method — nothing added, nothing
   dropped.

7. **Wire it into `src/app.ts`** (see `references/examples/app.ts`). Add
   the route import alongside the other route imports, and add
   `app.use('/<kebab-base>', <base>Routes);` in the *protected* section
   (after `app.use(getTokenPayload)`), next to the other protected route
   registrations — every generated endpoint is role-gated, so it always
   belongs after that line, never before it.

8. **Format everything you touched.** Run `npx prettier --write` and
   `npx eslint --fix` scoped to exactly the files this task changed — the
   new controller/route/types files, `helpers.ts`, plus `app.ts` — not the
   whole-tree `npm run format` / `npm run lint:fix`, which glob all of
   `src/**/*.ts` and would reformat unrelated files that have nothing to do
   with this endpoint.

9. **Typecheck.** Run `npm run build` (this repo's `tsc --noEmit`
   equivalent — it also writes to `dist/`, that's fine, it's gitignored) to
   confirm zero TypeScript errors — that's the actual bar for "done" here,
   not a clean lint pass. Fix anything the build reports before finishing.

## Explicitly out of scope

Per the standing instructions for this skill: don't write tests, don't run
`db:sync`/create tables, and don't try to start the server to hit the
endpoint — the developer creates the tables and tests manually. Your job
ends at "code compiles cleanly and follows the existing patterns."

## Troubleshooting

**`Argument of type 'string | string[]' is not assignable to parameter of type 'string'`**
Cause: under Express 5's types `req.params.id` is `string | string[]`.
Solution: read it as `const id = String(req.params.id);` before using it in
a regex or a `where` clause.

**A bad `:id` returns 500 with a stack trace instead of 404**
Cause: the malformed UUID reached Postgres, which rejected it, and
`next(error)` has no error middleware to catch it.
Solution: guard with `UUID_REGEX.test(id)` at the top of the handler and
return the normal 404. Don't add error middleware to fix this.

**A valid request gets 422 "Missing required parameters"**
Cause: a required field was checked with `!field`, and the caller sent a
legitimate `0` or `false`.
Solution: use `isMissing` from `./helpers` in both the `if` condition and
the `details` object.

**The endpoint 404s on every request even though the files exist**
Cause: the `app.use('/<kebab-base>', ...)` registration is missing from
`src/app.ts`, or it was placed before `app.use(getTokenPayload)` and the
role check has no token payload to read.
Solution: register it in the protected section, after that line.

**Unrelated files show up as modified in `git status`**
Cause: `npm run format` / `npm run lint:fix` were run — they glob all of
`src/**/*.ts`.
Solution: revert those files and re-run prettier/eslint scoped to just the
files this task created or edited.
